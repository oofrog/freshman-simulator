# 사용자 테스트 과제 — 진행자용 정답·기록표 (#42)

참가자 화면(`mock/lab.html`)에는 미션 문구만 보인다. 이 문서는 진행자만 본다. 미션 문구는 `mock/lab.js`의 `STEPS[].task`에 있다.

- 사전 과제와 확인 과제는 문항 구성과 난이도가 같고 과목만 다르다. 두 과제를 비교해서 튜토리얼 효과를 본다.
- 두 단계 모두 목업을 새로 열어서 시작 상태가 같다. 영어회화1(20003, 2학점)만 신청된 상태다.
- 제한 시간은 5분이다. 위쪽 바에 "경과 m:ss / 5:00"이 나오고, 넘으면 빨갛게 바뀐다. 강제로 넘기지는 않는다.

## 정답

| 문항 | 사전 과제 | 확인 과제 |
|---|---|---|
| 1. 찾아서 신청 | 「대학글쓰기」 → "신청되었습니다." (수업번호 20001) | 「AI와사고」 → "신청되었습니다." (수업번호 20002) |
| 2. 정원·희망인원 | 「영화로읽는심리학」 정원 40명, 희망인원 176명 | 「미술과치유」 정원 25명, 희망인원 140명 |
| 3. 신청 가능 여부 (말로) | 「경영학원론」 **신청 불가**. 이수제한 "경영학부 1학년만 허용" | 「프로그래밍기초」 1반 **신청 가능**. 이수제한 "1학년 허용 / 소프트웨어학부만" |
| 4. 신청 과목·총 학점 | 영어회화1 + 대학글쓰기, 총 4학점 | 영어회화1 + AI와사고, 총 4학점 |

- 1번은 수업번호 입력칸, 기본수업, 수강신청, 희망수업 어디서 신청해도 맞음으로 본다.
- 2번의 정원은 "제한인원", 희망인원은 "희망인원" 칸이다. 희망수업 화면에서 볼 수 있다.

## 진행자 주의사항

- 목업은 이수제한으로 신청을 막지 않는다. 그래서 3번은 말로만 답하게 하고, 진행자가 답을 받아 적는다. 참가자가 신청 버튼을 눌러 버리면 "신청되었습니다."가 떠도 3번 답으로 보지 않고, 4번의 학점이 바뀌니 기록표 메모에 적는다.
- 3번 정답이 두 과제에서 다르다(불가/가능). 이수제한을 읽는 방법이 같으므로 난이도는 같다고 본다.
- 2번 희망인원은 참가자가 그 과목을 희망수업에서 삭제하거나 다시 담으면 1씩 바뀐다. 그런 경우에는 바뀌기 전 숫자를 정답으로 본다.
- 4번은 참가자가 다른 과목을 더 신청했다면 그 상태 그대로 말한 것이 맞는지로 판단하고, 메모에 적는다.

## 실전 재현 (4회)

- 1회차는 사용법 설명을 겸한 연습이다. 진행자가 화면을 같이 보며 시계, [신청], 대기 화면, [결과 보기]를 설명하고 참가자가 그냥 눌러 본다.
- 2~4회차는 참가자 혼자 한다. 설문 3페이지("실전 재현을 3회 해 본 뒤")는 이 3회를 말한다.
- 요약 CSV의 실전 재현 번호는 1~4 그대로 나온다. 분석할 때 1번은 연습으로 빼고 2~4번을 본다.

참가자 번호: ______ (설문 1번, 실험 페이지 번호와 같게)

| 과제 | 1번 | 2번 | 3번 | 4번 | 끝낸 시간 | 막혀서 물어본 지점 |
|---|---|---|---|---|---|---|
| 사전 과제 | 맞음 / 틀림 / 못 함 | 맞음 / 틀림 / 못 함 | 맞음 / 틀림 / 못 함 | 맞음 / 틀림 / 못 함 | _:__ | |

- 끝낸 시간: 참가자가 "다 했어요"라고 말한 때의 위쪽 바 경과 시간. 5분 안에 못 끝내면 "5:00 초과"로 적는다.
- 막혀서 물어본 지점: 참가자가 질문하거나 오래 멈춘 곳과 그때 경과 시간 (예: "2:10 희망인원이 어디 있는지 물어봄").
